# Conduit

The `conduit` chart deploys the Conduit tunnel broker server. Remote agents dial
out to it over mTLS gRPC and expose HTTP services back through the broker.
Agents are not deployed by this chart; they run at remote sites using configs
generated by the server's admin API (`GET /agents/{id}/k8s`).

Enable it from the umbrella chart with `conduit.enabled: true`.

## How it works

- **Leader election.** Replicas compete for a Lease; the winner labels its own
  pod `conduit-role=active`, and `conduit-service`, `conduit-admin-service` and
  `conduit-grpc-lb` select only that pod. Standbys are Ready but receive no
  traffic. `replicaCount > 1` requires `leaderElection.enabled` (the chart fails
  to render otherwise).
- **Certificates.** The server always uses the `kubernetes` cert backend: the CA,
  server cert and per-agent certs live in Secrets (`conduit-ca`,
  `conduit-server`, `conduit-agent-<id>`) in the release namespace. They are
  created at runtime, not by Helm, so `helm uninstall` leaves them in place.
- **Server cert SANs.** The in-cluster service names are always included. Set
  `grpcLoadBalancer.hostname` to the DNS name remote agents dial, otherwise they
  fail hostname verification. Extra names go in `serverConfig.server_names`.
- **Server config.** `serverConfig` is rendered into `server.json` as-is
  (snake_case keys). Listen addresses, `cert_backend`, `kubernetes` and
  `leader_election` are owned by the chart.

## Exposing it

- **gRPC (agents).** Agents use mTLS end to end, so the gRPC endpoint must be an
  L4 passthrough load balancer, never revproxy or an L7 ingress. On AWS:

  ```yaml
  conduit:
    grpcLoadBalancer:
      enabled: true
      hostname: conduit.example.org
      annotations:
        service.beta.kubernetes.io/aws-load-balancer-type: "nlb"
        service.beta.kubernetes.io/aws-load-balancer-scheme: "internet-facing"
  ```

  With `global.netPolicy.enabled`, a NetworkPolicy admits
  `grpcLoadBalancer.allowedCIDRs` to the gRPC port.
- **HTTP (tunnel traffic).** `conduit-service` port 80. Either route to it from
  revproxy or enable the chart's own `ingress`.
- **Admin API.** `conduit-admin-service` serves agent private keys and has no
  auth of its own. Keep it ClusterIP and use
  `kubectl port-forward svc/conduit-admin-service 9090`, then open
  `http://localhost:9090/ui`.
